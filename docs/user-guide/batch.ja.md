# バッチ処理

[← ドキュメント](../README.ja.md) ・ [← SmartCut](../../README.ja.md) ・ [English](batch.md)

SmartCut は、一晩ぶんの録画をまとめて片付けることを前提に作られています。20 本を
放り込み、`Ctrl+A` → `Ctrl+D` を押し、編集画面で 1 本ずつ切って、最後にまとめて
書き出す、という流れです。

このページでは、その間に裏で何が動いているのか、そしてなぜそれが作業の邪魔に
ならないのかを説明します。

## 作業の流れ

```
ファイル追加  →  裏で索引作り  →  Ctrl+D で CM 検出
              →  編集画面で 1 本ずつ切る  →  一覧をまとめて書き出す
```

カットは編集ウィンドウではなくクリップ側に残ります。そのため一覧を上から順に
切っていき、そのあとでまとめて書き出す、という進め方ができます。

## 2 本のキューが並行して走る

裏で動くキューは 2 本あります。**1 本はシーク用インデックスを作り、もう 1 本は
CM を検出します。** 同じ種類の処理は同時に 1 つずつ、違う種類なら 2 つ同時に
走ります。

キューを分けているのは、2 つの処理の重さが違うからです。索引作りはキーピクチャを
すべて復号するので全コアを使います。CM 検出は字幕ストリームを読むか、音声とロゴを
見るかで、いずれも libavcodec のスレッド化が効きません。1 コアと、大量の
ディスク待ちです。索引作りが分け合うことで失うものより、CM 検出が得るものの
ほうがずっと大きく、これが「夜に `Ctrl+D` を押して朝までに終わる」という結果に
つながっています。

3 本目のキューはありません。3 本目は同じコアを使う 2 つ目のデコーダになりますし、
それ以前にディスクが上限になります。3 つの答えが遅く出るより、2 つが早く出て
3 つ目がその後に続くほうがましです。

## 編集画面はキューを待ちません

索引作り・CM 検出・カット編集は同時に動きます。3 つは何も共有していません。
索引作りも検出も書き出しも、ディスク上のシーク用インデックスから録画を開き直す
ので、12 本目に長い処理が走っていても、いま編集しているクリップには何の影響も
ありません。

編集ウィンドウが開いているあいだ、裏の 2 本のキューはマシンの**半分**だけを
分け合います。ポインタの下にある絵こそ人が待っているものであり、裏の処理が
数秒遅く終わることはそのための妥当な対価です。

**まだ読み込みが終わっていないクリップも開けます。** 編集画面は自分でその処理を
行い、途中まで読めたところまでを表示します。キューの順番を待っても得るものは
ありません。編集画面がそのクリップを持っているあいだ、索引作りのキューはその行を
飛ばします。同じファイルを二重に読むことこそ避けたい事態であり、譲るのはキューの
側です。編集画面が書いた索引はディスクに残るので、編集画面を閉じてキューがその行を
取り上げるときには、読み込み 1 回ぶんで済みます。

## 一覧全体に CM 検出をかける

`Ctrl+A` → `Ctrl+D` で、選択したすべてのクリップの検出がキューに積まれます。
18 本を選んで `Ctrl+D` を 1 回押せば、一晩ぶんの作業がキー操作 1 回で始まります。
これがこの機能の目的です。その間、まだ索引の無いクリップの読み込みも並行して
進みます。

進み具合は各行に出ます（`CM 検出中 84% — ロゴを探しています`）。まだ順番の来て
いない行は `CM 検出 待機中` と表示されます。

**解析を中止**を押すと両方のキューが止まり、もう一度押すと再開します。索引作りは
ファイルの途中でも止まれますが、CM 検出を構成する 3 つの処理は途中で止まれないので、
停止はクリップとクリップの**間**で起こります。

停止の対象は「いま動いているもの」だけで、そのあとに続くものには影響しません。
そのため、バッチを止めてすぐ別のバッチを始められます。

## クリップの複製

**⧉ クリップを複製**は、同じ録画をもう 1 行足します。2 時間の録画に番組が 2 本
入っている場合のための機能です。同じファイルを 2 行に置き、それぞれ違う範囲で
書き出します。

**複製はカットも印も引き継ぎます。** 2 本目のカットは、ゼロから始めるものでは
なく 1 本目をずらしたものであることがほとんどです。編集内容を捨てるコピーでは、
複製の目的を果たせません。索引・尺・CM 検出の結果も引き継がれます。どれも同じ
ファイルについての答えなので、複製にディスクの読み直しは発生しません。

同じ録画が一覧に複数ある場合、出力ファイル名には一覧順に `_1` `_2` が付きます。
これが無いと 2 本目のカットが 1 本目を上書きしてしまいます。片方を消すと、残った
ほうは番号の無い名前に戻ります。番号は複製時に刻み込むのではなく、そのつど一覧
から数えているためです。

## 一覧を書き出す

出力タブは一覧を上から順に、1 本ずつ書き出します。各行に進み具合と結果が出て、
その上に全体の状況・経過時間・残り時間が出ます。

`出力中止` は、いま書き出しているクリップを最後まで書き終えてから止まります。
途中まで書かれたファイルが残ることはありません。

書き出しの順序は一覧の順序なので、「これを最初に書き出したい」というときは
その行を上へドラッグします。

## ネットワーク共有上の録画を扱う

SMB 共有上の録画は、コマンドラインの引数としても、ファイルマネージャーからの
ドロップとしても、出力先フォルダーとしても扱えます。SmartCut は共有パスを
「このマシンで実際にマウントされている場所」に読み替えます。それ以降は普通の
パスなので、パケット走査もシーク用インデックスも書き出しも、ネットワークが
関わっていることを知らないまま進みます。

**SmartCut 自身はマウントを行いません。** マウントにはパスワードが伴い、それは
カット編集ソフトではなくデスクトップのキーリングが持つべきものだからです。
つながっていない共有は、開くべき場所を示して断ります。

```
\\nas\rec につながっていません。ファイルマネージャーで smb://nas/rec を
開いてから、もう一度追加してください。（現在つながっている共有: \\nas\録画）
```

## バッチを保存する

一覧全体（録画・カット・トラックの選択・出力設定）は `Ctrl+S` でプロジェクトとして
保存でき、次回そのまま戻ってきます。[プロジェクト](projects.ja.md)を参照して
ください。
