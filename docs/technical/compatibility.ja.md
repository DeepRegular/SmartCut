# 互換性

[← ドキュメント](../README.ja.md) ・ [← SmartCut](../../README.ja.md) ・ [English](compatibility.md)

SmartCut を更新したとき、何がそのまま使えて何が使えなくなるかをまとめる。
これは 1.0 に向けた方針である。0.8 系はほぼ毎週変わってきたが、
何も約束していなかった。0.8.21 までの版はこの方針どおりに動かない点があり、
その違いは[末尾](#0821-までの版)にまとめた。

SmartCut がディスクに残すものと、ほかのプログラムが当てにできるものを、
3 つに分ける。

| 区分 | 1.x のあいだ | 例 |
|---|---|---|
| [保つもの](#保つもの) | 変えない。変えるときは 2.0 にする | `.scproj`、CLI のオプションと終了コード、読み戻すマークファイル、BDAV フォルダーへの追記 |
| [引き継ぐもの](#引き継ぐもの) | 形が変わっても移し替える。変えたらリリースノートに書く | 環境設定、出力プリセット、バッチのキュー、[ビルド](building.ja.md)に載っている環境変数 |
| [保たないもの](#保たないもの) | 変わりうる。必要なら SmartCut が作り直す | キャッシュ、CLI の表示文言、ログ、出力ファイルのバイト列 |

## バージョン番号

1.0 からは `MAJOR.MINOR.PATCH` の意味を次のように決める。

| 桁 | 上げるとき | 例 |
|---|---|---|
| `PATCH` | 不具合を直したとき | カットで落ちていた字幕が残るようになった |
| `MINOR` | できることが増えたとき、既定値を変えたとき | 出力の選択肢が増えた。`.ts` 出力で放送のテーブルを既定にした |
| `MAJOR` | [保つもの](#保つもの)の扱いが変わるとき | 2.0 が 1.x の `.scproj` を違う意味に読む |

0.8 系はこの決まりに従っていない。何も約束していなかったので、
新機能も PATCH で出してきた。

既定値の変更は MAJOR ではなく MINOR とする。
同じオプションで実行しても出力が変わることはあるが、
各オプションの意味は変わらないからである。
既定値に頼っているスクリプトのために、変えたことはリリースノートに書く。

## 保つもの

### プロジェクトファイル（`.scproj`）

`.scproj` には形式の番号が `smartcut` という項目で入っている。
これは [`PROJECT_VERSION`](../../gui/src/app.js) の値で、
プログラムのバージョンとは別物である。
プロジェクトを保存できるようになってから、ずっと 1 のままである。

- 1.x はどれも、0.8 系と 1.x が書いたすべての `.scproj` を開ける。
- **知らない番号（自分より大きい番号）のファイルは開かない**
  （[プロジェクト](../user-guide/projects.ja.md#新しいバージョンで作ったファイル)）。
- 1.x のあいだ番号は 1 のままにする。新しい情報は項目を足して書く。
- 知らない項目は残したまま保存し直す。
- 既存の項目の意味は変えない。意味を変えたいときは別の項目を足し、
  古い項目も書き続ける。
- 番号を上げるのは MAJOR だけにする。上げた版も、古い番号のファイルは開ける。

知らない項目を残すのは、次の場所に限る。

| 場所 | 項目 |
|---|---|
| ファイルの最上位 | `smartcut`・`saved`・`settings`・`clips` と並ぶ項目 |
| 出力設定 | `settings` |
| 行 | `clips` の各要素 |
| 行の編集内容 | `edit` |
| 行のトランジション | `after` |

次の 2 つは残さない。そのため、後の版はどちらにも頼らない書き方をする。

| 残さないもの | 理由と、後の版の書き方 |
|---|---|
| リストの要素の中の項目（`cuts` のカット範囲、`cmBlocks` のブロック、`detectedWith` の中身） | カット編集がこれらのリストを知っている項目だけで書き直すので、行を開いて保存すると消える。カットについて新しい情報を持たせるなら、範囲ごとではなく `edit` の項目にする |
| 知っている項目に入った知らない値 | 後で足されたトランジションの `kind` は「トランジションなし」として読む。継ぎ目のウィンドウでその継ぎ目を開いて確定すると、なしで書き戻す。新しい種類は新しい項目として足し、元の項目にはこの版が知っている近いものを書く |

知らない番号のファイルを開かないのは、開くと知らない項目が落ち、
上書き保存でそれが確定するからである。
知らない項目を残すのも、同じ理由による。
1.1 で足した項目を 1.0 が開いて保存すると、残さない限りその項目は消える。

自動保存の複製は、`.scproj` を `{recovered, project, doc}` で包んだものである。
扱いは `.scproj` と同じで、新しい版が書いた複製は案内せずにそのまま残す
（[自動保存と復元](../user-guide/projects.ja.md#自動保存と復元)）。
バッチのジョブも `.scproj` なので、ある版で積んだキューは次の版でも処理できる。

### 読み戻すマークファイル

| ファイル | 保つ形 |
|---|---|
| `.keyframe` | 1 行に 1 つのフレーム番号。数でない行は読み飛ばすので、他のソフトが付ける見出し行があっても読める |
| `.trim.avs` | `Trim(a,b)` を `++` でつないだもの |
| `.cm.json` | [設計ノート](design.ja.md#cm-検出結果のサイドカー)の形。`smartcut_cm` が形式の番号で、いまは 1 |
| `.cue` | 読むだけ。各 `TRACK` の `INDEX 01` を使う |

`.cm.json` の扱いは `.scproj` と同じとする。
項目は変えずに足し、`smartcut_cm` が知らない番号なら読まない。
`smartcut_cm` の無いファイル（手で書いたものや他のソフトが書いたもの）は、
これまでどおり読む。

### コマンドライン

| 決まり | |
|---|---|
| オプションの名前と意味は 1.x のあいだ変えない | 名前を変えたときは、古い名前も 2.0 まで受け付ける。いまの `--no-tables`（`--tables muxer` と同じ）がその例 |
| 知らないオプションはエラーにする | 新しい版向けのスクリプトを古い版で動かしたとき、違う動作をせずに止まる |
| 終了コードは成功で 0、失敗で 1 | `--verify` でフレームの不一致が見つかれば 1。音声の長さの差は警告だけで 0 |
| それ以外の終了コードは不具合 | 101 は Rust のパニックである |
| `--version` は `smartcut X.Y.Z` の 1 行だけを表示する | スクリプトが版を確かめるときに使う |
| GUI の引数は録画とプロジェクトのパス、それに `--batch` | `--queued` はバッチツールが開くウィンドウとのやりとり用で、外から使うものではない |

**CLI の表示内容は保たない**（[保たないもの](#cli-の表示)）。

### ディスクフォルダーへの追記

`--bdav` は、すでに BDAV のディスクが入っているフォルダーに書き足せる。
既存のファイルの番号の続きから振るので、上書きはしない。
以前の版やレコーダーが書いたフォルダーにも、後の版から追記できる。

### SmartCut が自分のファイルを置く場所

アプリの識別子は `dev.smartcut.app` である。
SmartCut が自分のファイルを置くフォルダーは、すべてこの名前から決まる。

| 置くもの | 例 |
|---|---|
| キャッシュ | シーク用インデックス、プロキシ、検出結果 |
| 設定のフォルダー | バッチのキュー、ウィンドウの位置 |
| データのフォルダー | 自動保存の複製、実行ログ |
| webview の保存領域 | 環境設定、出力プリセット |

識別子を変えると、これらが一度に置き去りになる。そのため識別子は変えない。

## 引き継ぐもの

### 環境設定

環境設定は webview の保存領域に、1 項目 1 キー（`smartcut.<名前>`）で入っている。
形式の番号は持たない。
読むときに項目ごとに型を確かめ、選択肢がある項目は選択肢の中にあるかも確かめる。
合わない値は既定値に置き換える。新しく増えた項目を初めて読むときも、この経路を通る。

項目の名前や単位を変えるときは、次の版で古いキーを読んで新しいキーへ移し、
古いキーを消す。
これまでに 1 回だけ行った。
`blankBlackLevel` と `blankWhiteLevel`（0〜255 の割合）を、
`blankBlack` と `blankWhite`（% 表記）に移した
（[prefs.js](../../gui/src/prefs.js) の `carryLevels`）。

なくした項目は読まないだけで、別の意味に使い回さない。

### 出力プリセット

同じ保存領域の `smartcut.outputPresets` に、名前と出力設定の組を並べて持つ。
プリセットに含まれない設定は、適用するとき既定値になる。
そのため、ある設定が増える前に保存したプリセットもそのまま使える。
値の型が合わないときは `.scproj` と同じく読む。
文字列を入れる設定に数値が入っていれば文字列に直し、それ以外は既定値にする。

### バッチのキュー

設定のフォルダーの `batch.json` に、ジョブとその状態、
キューが空になったあとの動作を持つ。
ある版が残したキューは、次の版がそのまま引き継ぐ。
キューにもジョブにも、知らない項目があれば残して書き戻す。

### ウィンドウの位置

設定のフォルダーの `windows.json` に持つ。
読めないときは、各ウィンドウを初回起動と同じ位置に開く。

### 環境変数

[ビルド](building.ja.md)に載っているものは、環境設定と同じく引き継ぐ。

| 変数 | |
|---|---|
| `SMARTCUT_PROXY`、`SMARTCUT_PROXY_WIDTH`、`SMARTCUT_PROXY_QUALITY`、`SMARTCUT_PROXY_ENCODER` | プロキシ |
| `SMARTCUT_BYTE_SEEK` | シークの方法 |
| `SMARTCUT_FFMPEG_LOG`、`SMARTCUT_CLEAN_JOINS` | 環境設定の初期値 |

これ以外の `SMARTCUT_*` はデバッグ用とテストスクリプト用で、
予告なく変えることがある。

## 保たないもの

### キャッシュ

次のキャッシュは、それぞれ独自の番号を持つ。
番号はファイル名のハッシュに含まれる。
読み方が変わった版は別の名前を探すので、古いファイルは見つからず、
新しく作り直される。

| キャッシュ | 番号 | 定義 |
|---|---|---|
| シーク用インデックス（`.scix`） | `seek_index::VERSION` | [seek_index.rs](../../rust/crates/core/src/seek_index.rs) |
| プロキシとピクチャ種別の表 | `proxy::VERSION` | [proxy.rs](../../rust/crates/core/src/proxy.rs) |
| CM 検出 | `CM_VERSION` | [lib.rs](../../gui/src-tauri/src/lib.rs) |
| 波形 | `WAVE_VERSION` | 同上 |
| 黒白検出 | `FLAT_VERSION` | 同上 |
| 無音検出 | `QUIET_VERSION` | 同上 |

古いファイルは、キャッシュの上限か「すべて削除」で消えるまで残る。
キャッシュにしか無い情報は無いので、消えて困るものは無い。

番号を上げるのは、古いファイルを読むと結果を誤るときだけにする。
上げると、更新した人の一覧にある録画すべてで作り直しが起きる。
古いファイルを読んでも支障が無い変更なら、番号は上げない。

### CLI の表示

CLI の表示は人が読むためのものである。
文言も並びも見出しの言語も、どの版でも変わりうる。
`--analyze` や `--detect-cm` も含め、出力を機械で読むことは想定していない。
スクリプトで結果を判定するときは、終了コードと `--version` を使う。

### ログ

実行ログ（ログのフォルダー）と `--log` のファイルは、先頭行にバージョンを書く。
それ以外の中身は保たない。

### 出力ファイルのバイト列

同じ録画を同じ設定でカットしても、版が違えば同じファイルになるとは限らない。
保つのは、カットとして正しいことである。

- 無劣化コピーした部分は、録画のバイト列そのものである
- 指定した区間が、同じ位置に同じフレーム数で再生される

版によって、あるいは同じ版でも実行のたびに変わりうるものは次のとおりである。

| | 理由 |
|---|---|
| 再エンコードした継ぎ目 | 同梱の FFmpeg のエンコーダで書くので、FFmpeg が変われば変わる |
| `.iso` | UDF のイメージに書いた時刻が入る |
| `.mp4`・`.mkv` | libavformat が自分のバージョンを書き込む。Matroska は毎回別の Segment UID を振る |
| 不具合の修正が及ぶ部分 | カットの誤りを直す PATCH は、当然出力を変える |

継ぎ目のバイト列以外で出力が変わる変更は、リリースノートに書く。
公開の前に、決まった録画で CLI の出力を前の版と比べる。
差があり、それがリリースノートの変更で説明できなければ公開しない。

## 0.8.21 までの版

この文書の内容のうち次の点は、0.8.21 のあとで実装した。
それより前の版はまだ使われているので、違いを挙げておく。

| 項目 | 0.8.21 まで | それ以降 |
|---|---|---|
| `.scproj` の知らない項目 | 読み込みで落ち、次の保存でファイルからも消える。行の編集内容（`edit`）の中だけは、カット編集で開くまで残る。新しい版のファイルをこれらの版で開いて保存すると、その項目は消える | どの階層でも残して書き戻す |
| `.cm.json` の `smartcut_cm` | 1 を書くだけで読まない | 知らない番号なら読まない |
| `batch.json` の知らない項目 | 読み飛ばし、次の書き込みで消える | 残して書き戻す |
| プリセットの、文字列を入れる設定に入った数値 | 既定値に戻る（`.scproj` では文字列に直して読んでいた） | 文字列に直して読む |
| `--version` | 無い。版は `--log` のファイルの先頭行にしか出ない | `smartcut X.Y.Z` を表示し、0 で終わる |
