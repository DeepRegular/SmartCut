# BDMV / BDAV への拡張（調査ノート）

[← ドキュメント](../README.ja.md) ・ [← SmartCut](../../README.ja.md) ・ [English](bdmv.md)

**結論: 実現可能であり、最初の段階はすでに動いている。**

確認した内容は次のとおり。

| 項目 | 状況 |
|---|---|
| **M2TS（192 バイトパケット）の読み込み** | **無修正で動く。** 実素材を M2TS に再多重化したもので 450/450、96.2% 無劣化、A/V 17.7 ミリ秒 |
| `bluray:` プロトコル | この ffmpeg は `--enable-libbluray` でビルドされており、自前のバイナリからも到達できる（`-playlist` / `-angle` / `-chapter` オプション付き） |
| AC-3 音声（BDMV の定番） | MP4 出力まで通る |
| **BD LPCM（`pcm_bluray`）** | **MP4 でも MKV でも不可**。TS では `bin_data` に劣化する。標準 PCM への変換が必要 |
| BDAV のプレイリスト（`.rpls`） | libbluray は BDMV 専用。自前のパーサが必要 |

**暗号化されたディスクは対象外である。** 復号を前提とするものは一切扱わない。

## 作業の段階

1. **単一の `.m2ts` を切る** — 完了。追加作業なし。
2. **BDMV をプレイリスト単位で切る** — `ff::format::input_with()` に切り替え、
   `playlist` オプションを渡す。小さい。
3. **BDAV のプレイリスト対応** — `.rpls` を自前で読む。形式は単純で、PlayItem
   （クリップ参照と IN/OUT 時刻）の並びだが、書く必要はある。
4. **BD 固有のストリーム** — LPCM の変換、PGS 字幕、TrueHD/DTS-HD、VC-1。音声の複数
   トラックはすでに扱っており、それぞれ独立に切っている。ARIB 字幕ストリームも同様
   である。したがって BD が加えるのはコーデックと、文字ではなく絵のストリームである
   字幕形式である。映像トラックは依然として 1 本のみ。
5. **BDMV/BDAV として書き出す** — これはオーサリングであり、別の問題である。大きい。

## 索引のソースは差し替え可能（実装済み）

アクセスポイント索引の作り方は
[`index.rs`](../../rust/crates/core/src/index.rs) の `IndexSource` トレイトとして
切り出してある。BD の CLPI EP マップを読む実装は、そこに足すだけでよい。

| 実装 | 内容 |
|---|---|
| `PacketScan` | 全パケットを走査する。正確で、どのコンテナでも動く |
| `ContainerIndex` | コンテナのシークテーブルを読む（MP4 の `stss` など） |
| `SeekIndex` | 以前の走査結果を書き出したものを読み直す（[シーク用インデックス](design.ja.md#シーク用インデックスseek_indexrs)） |
| （将来）`ClpiIndex` | BD の CLIPINF EP マップを読む |

`--index scan|container` で切り替えられる。実際の 654 MB の MP4 での測定値は次の
とおり。

```
container    2.73s   アクセスポイント 430 個
scan        56.44s   アクセスポイント 430 個   <- 計画はバイト単位で一致
```

### なぜ「時刻だけ」で足りるようにしたのか

以前はコピー区間を「復号順のパケット数」で区切っていた。これは全パケット走査でしか
得られない。外部の索引が持っているのは時刻なので、**終端のアクセスポイントの時刻に
達したら止める**方式に変えた。leading picture の除去も同様に時刻ベースの規則、
つまり「エントリポイントより前に表示されるパケットを捨てる」に変えた。その結果、
索引がどこから来たかを気にしないカッターになった。

### 外部の索引に答えられないこと

索引が知っているのはエントリポイントの位置だけである。GOP がオープンかどうか、
その leading picture が参照されるかどうかは、ビットストリームを見なければ分からない。
そこで索引は「自分が答えられたかどうか」を申告し、`refine_leading()` が
**そのカットが実際に使うアクセスポイントの周辺だけ**を読んで穴を埋める。ファイルを
もう一度通して読むことはない。

### 途中で踏んだ罠 2 つ

- **コンテナのシークテーブルは DTS を鍵にしている。** B ピラミッドがあると PTS との
  差が一定にならないので、単純な補正では合わない。最終的に「窓の中で DTS で照合し、
  そのあと PTS を読み直す」形になった。
- DTS で照合するようにすると、**目的のキーフレーム自身の PTS がすでに「次の GOP」の
  停止条件を満たしてしまう**ので、窓が即座に閉じて leading picture が 1 枚も見えなく
  なる。停止条件は目的のフレーム自身ではなく、次のアクセスポイントで評価する必要が
  ある。

### 検証

13 ケースのうち 9 ケース（TS 以外すべて）が、`--index container` で走査と同一の結果を
返す。MPEG-TS はシークテーブルを持たないので明示的なエラーを返す。それが
**まさに BD の CLPI が埋める穴**である。
